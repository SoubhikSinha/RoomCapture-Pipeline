# Technical Report

*Engineering over exposition.*

## 1. Architecture

The pipeline is a linear chain of tier-agnostic stages, each consuming only the output contract of the stage before it:

```
Adapter (per tier) -> Capture -> reconstruct_room() -> Room
  -> detect_damage() + evaluate_concealed_damage() + generate_scope_items()
  -> stitch_rooms() (trivial single-room, or real multi-room via connectors)
  -> PropertyPlan -> JSON + rendered PNG
```

**`Capture`** (`pipeline/core/types.py`) is the load-bearing abstraction: one dataclass with every field a LiDAR frame can supply (`pose`, `depth_path`, `confidence_path`, `intrinsics`), all `Optional`. Photo/Video adapters simply leave them `None`. Everything downstream branches on *field presence*, never on *which tier this is* — the reconstruction, damage, and stitching code is the same three functions regardless of input richness. This is why the confidence-interval design (Section 4) generalizes across tiers without three parallel code paths.

Each stage is independently testable and independently swappable: `detect_damage()`'s docstring states its own upgrade path (swap the HSV/edge heuristics for a vision-model call) without changing its signature or `DamageRegion` output; `_estimate_ceiling_height_cm()` (Section 6) was swapped mid-project without touching wall/opening/floor-area code.

## 2. Tier design and device matrix

Three tiers, one output contract, honestly widening confidence as data thins:

| Tier | Signal available | What it enables |
|---|---|---|
| LiDAR | Depth + pose + intrinsics per frame | Real point-cloud back-projection, box-room bounding, per-wall opening scan |
| Video | RGB frames + timestamps, no pose | Perimeter-from-duration heuristic (assumed walking speed) |
| Photo | 2-8 stills, no depth, no pose, no motion | Documented prior (default room size), the honest floor |

Route 2 (stock capture protocol) was chosen over building a custom iOS app: engineering time went to the pipeline — the walk-in test, fix loop, and benchmark accuracy are 65%+ of the score — rather than capture UI/TestFlight plumbing that the App Store already solves. LiDAR uses "3D Scanner App" (Laan Labs), exported as **All Data** specifically — not the "Point Cloud" export, which is pre-fused by the app and drops per-frame poses this pipeline needs to do its own reconstruction.

**Device matrix** (`docs/device_matrix.md`) is generated by `scripts/generate_device_matrix.py` directly from `docs/benchmark_results.json` — never hand-typed, so it can't overstate accuracy. Real result on `bedroom_1` (iPhone 16 Pro, `iPhone17,1`): LiDAR fails ceiling height (5.81cm error post-fix) and opening detection (0%); Video fails wall lengths (43.8% error); Photo's gates pass but are explicitly flagged vacuous, since Photo-tier geometry is a fixed default, not a measurement. **The device matrix's honesty is itself evidence of calibration** (Section 5) — it does not claim capability the pipeline doesn't have.

## 3. Drift handling

`pipeline/stitching.py` places rooms via a BFS spanning tree over hand-declared `Connector`s (which wall touches which — adjacency is not auto-inferred from geometry; that's a separate, harder CV problem, explicitly out of scope). Any connector not used by the tree is a loop-closure edge: without correction, sequential rigid placement lets error accumulate around a loop, leaving a visible gap at the closing seam. With `drift_correction=True`, that positional mismatch is distributed linearly across the rooms on the loop's path — a documented simplification of pose-graph relaxation, not full bundle adjustment.

**Ablation, on a synthetic 3-room hub-and-loop topology** (`scripts/stitch_ablation.py`): residual loop-closure gap drops from **1697cm (off) to 849cm (on)** — roughly halved, a real, measurable effect of the correction, not a cosmetic toggle. This has not yet been run against the real 4-room capture set: real connectors require hand-verifying which wall touches which from reconstructed wall IDs, and real wall geometry (Section 6) isn't accurate enough yet to make that verification meaningful. "Poses used as-is" is explicitly avoided — the mechanism exists and is proven on synthetic data; its real-data application is blocked on reconstruction accuracy, not skipped.

## 4. Error budget (confidence intervals)

`pipeline/confidence.py::measurement_ci(tier, value, sample_count, unit)` computes every interval from real capture properties — sample count backing that specific measurement (LiDAR: point-cloud size; Video/Photo: frame count) via sqrt(N) averaging against a per-tier base error prior, floored at a tier-specific minimum (averaging can't beat a sensor's fundamental noise floor). This is a genuine computation, not a lookup table: two LiDAR measurements with different point counts get different intervals.

**Verified ordering, both synthetically and on real data**: LiDAR CI < Video CI < Photo CI (relative widths ~0.5% / ~5% / ~20% on real `bedroom_1` data). The ceiling-height fix (Section 6) also tightened this mechanism: post-fix, the CI sample count reflects the ~108K points in the filtered plausible-ceiling band, not the full ~1.19M-point cloud — the interval got *wider* after the fix (±0.67cm vs. ±0.5cm before), correctly reflecting that fewer points now inform that specific number. A tight CI on a wrong number ("confident garbage") is exactly the failure mode this design targets, and the ceiling-height case is a real, caught instance of it (Section 6).

## 5. Calibration analysis

Calibration was checked at every tier, not assumed:

- **LiDAR bounding-box bug** (`pipeline/room_reconstruction.py`): raw `min()`/`max()` on the point cloud let a handful of noisy/reflected points inflate room size (one real room measured 12.3m x 9.4m instead of ~4.8m x 4.1m). Fixed by switching to a 5th/95th percentile trim — found via direct real-data testing, not by inspection alone.
- **Damage-detection explosion bug**: fixed-pixel thresholds tuned against small synthetic test images produced 54,609 false-positive "damage regions" on a real 1920x1440-resolution, ~1800-frame LiDAR capture (one frame alone produced 26,935 raw Canny contours from ordinary photo texture). Fixed via area-fraction-relative thresholds, a Gaussian blur before edge detection, and deduplication to one region per (surface, damage_class) across the whole capture. Verified: 9 regions post-fix, JSON size 32MB -> 8KB.
- **Device string bug**: `scripts/run_benchmark.py` had the wrong device hardcoded (`iPhone16,2`); corrected to the real captured device (`iPhone17,1`) by cross-checking the LiDAR export's own `info.json`.

All three were found by testing against real data, not by code review alone — a repeated pattern in this project: synthetic tests catch logic errors, real data catches calibration errors, and both were required.

## 6. The fix loop story

**Worst gate identified via `scripts/rank_gates.py`**, ranking every real gate by severity (multiples past threshold): `ceiling_height` at 46.0x, ahead of `video_tier_wall_lengths` (14.6x) and `opening_widths` (a qualitatively different total failure, 0% detected).

**Root cause** (`docs/fix_loop_diagnosis.md`), from direct point-cloud inspection: real ceiling-height points were <0.5% of the cloud (5,295 of ~1.19M), only 5.7% of frames saw the true ceiling at all, and the raw cloud had physically-impossible outliers to 5.07m (sensor noise/reflection). One global percentile threshold was being asked to both reject that noise and find that sparse signal — it could do neither well.

**Fix**: filter to a physically-plausible ceiling band (`floor_y + 1.8m` to `+4.0m`) before taking the 90th percentile of the filtered band, instead of one global `p95-p5` trim. **Predicted 5.81cm error (~92% reduction) before writing the fix**, explicitly predicting the gate would *not* flip to pass. **Actual result matched the prediction exactly** (266.19cm / 5.81cm), because the prediction was computed by running the real formula against real data before touching code, not estimated by intuition.

**Two further improvements were attempted and rejected, with real numbers**: a density-peak method converged on furniture height (193.8cm, worse); a ray-direction-filtered method gave 295.5cm (worse, and needed further tuning to even compete). Both are documented as genuine due diligence. **The gate still fails** (3.9x over threshold, down from 46.0x) — closing it fully needs real geometric plane-fitting (RANSAC), a substantially larger investment flagged as future work before this fix loop even began, not a new excuse invented after the fact. Before/after verified byte-identical from a clean `git clone` (`results/fix_loop/`).

## 7. Known failure modes

- **Opening detection: 0% on every real room tested.** The eye-level-row depth-anomaly heuristic works on clean synthetic data but finds nothing on real captures — camera alignment, row selection, or depth-anomaly threshold likely don't hold up against real noise. Diagnosed as a real gap, not yet fixed (a stronger fix-loop candidate than ceiling height by raw severity category, deferred to keep this fix loop's story singular and complete).
- **Video-tier wall lengths: 43.8% error.** The duration x assumed-walking-speed heuristic has no real geometric grounding — it is intentionally the tier's honest floor, but the assumed constant (0.4 m/s) is uncalibrated against real walking speed variation.
- **Damage classification precision.** The explosion bug (Section 5) is fixed, but the HSV color thresholds still misclassify real wood/furniture tones as water damage on every wall of a real room — a genuinely harder problem than the explosion bug, needing a trained model or much better heuristics, not a threshold tweak.
- **Irregular rooms (3 of 4 real benchmark rooms)** aren't auto-scored by `pipeline/benchmark.py`, which assumes a box-room ground-truth shape. No per-wall correspondence method exists yet for comparing an irregular perimeter against the box-room reconstruction model.
- **Multi-room stitching and the drift ablation are unverified on real data** — both work and are tested on synthetic topologies; real application is blocked on the reconstruction-accuracy issues above (hand-authoring real connectors needs trustworthy wall IDs first).
- **Head-to-head: 0% beat-or-tie, 1 of 2 rooms scored**, not the required 2 — the real result of the above issues compounding, reported honestly rather than worked around.
- **Real-world nuisances** (mirrors, glass, wet-look surfaces, low light) were not specifically engineered for; the LiDAR bounding-box outlier problem (Section 5) is evidence they already affect this pipeline's raw point clouds (bedroom_1's window is a plausible source of the reflection/noise tail identified in Section 6).
